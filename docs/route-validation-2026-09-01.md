# CalmRoute AI 真实路线工程验证

测试日期：2026-09-01  
测试对象：高德真实算路、沿途充电站 POI、目的地停车场 POI、途经点二次算路  
样本量：10 条公开地点路线

## 结论

| 指标 | 结果 | 口径 |
| --- | ---: | --- |
| 真实算路成功率 | 90% | 9/10 条返回至少一条有效驾车路线 |
| 充电站 POI 返回率 | 90% | 9/10 条返回至少一个沿途充电站 |
| 停车场 POI 返回率 | 90% | 9/10 条返回至少一个目的地附近停车场 |
| 途经点重算成功率 | 90% | 9/10 条将备选 POI 作为途经点后返回新路线 |
| API 中位响应时间 | 6.7 秒 | 基础算路与途经点重算请求合并统计 |
| 发生退避重试的场景 | 0 条 | 正式串行测试未触发限流或超时重试 |

这些结果证明了当前原型的工程链路可运行，但不证明用户更容易理解、更信任建议或驾驶更安全。

## 方法

1. 使用带城市与区县的公开地点，降低同名地点造成的地理编码歧义。
2. 每条场景先调用真实驾车算路，并检查充电站与停车场 POI。
3. 选择返回的第二个充电站（无第二个时使用第一个）作为途经点，再次调用真实算路。
4. 顺序执行场景；限流或超时最多退避重试两次。
5. 不采集用户身份、车辆位置或个人行程数据。

## 失败与风险发现

- 首轮以两条并发执行时，结果降至 50%，出现高德 QPS 限制和请求超时。正式矩阵改为串行执行，说明当前免费/低配额度下不应直接并发放大请求。
- 千岛湖景区场景返回地图引擎数据错误。产品已能回退到演示估算，但仍需增加“选择景区入口或附近停车场”的恢复路径。
- 宁波至象山样本距离明显异常。接口成功只能证明链路通畅，不能证明地理编码语义正确；后续应展示解析后的完整地址，要求用户确认后再规划。
- POI 接口只提供地点信息，当前没有实时空闲充电桩、排队、价格或停车余位数据。

## 下一轮改进

1. 在算路前展示起终点解析地址，增加用户确认。
2. 景区终点不可达时，自动搜索入口或停车场并提供选择。
3. 对第三方接口增加缓存、限流队列与可观测错误码。
4. 有条件时再开展用户理解度与建议接受度测试；在此之前不展示虚构体验指标。

## 复现

本地服务启动后执行：

```bash
npm run validate:routes -- http://localhost:3000
```

脚本会输出完整 JSON，包括每条路线的成功状态、距离、时间、POI 数量、响应延迟、重试次数和错误原因。
