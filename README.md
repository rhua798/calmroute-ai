# CalmRoute AI · 安心领航

> 面向智能座舱的 AI 主动式出行助手。让每一次出发，都有把握。

**[体验在线 Demo](https://calmroute-ai.huangruoxuan0208.chatgpt.site/#demo)** · **[阅读完整案例研究](https://calmroute-ai.huangruoxuan0208.chatgpt.site/case-study)**

CalmRoute AI 是为“数字产品－导航体验经理”校招方向设计的个人作品集项目。用户可以用自然语言描述出发地、目的地、时间、电量、同行人与偏好；系统将需求转成结构化约束，调用真实地图服务生成路线，并在充电排队、错过出口、道路异常和停车困难等场景中给出可解释、可执行的下一步建议。

## 为什么做这个项目

传统导航擅长回答“怎么走”，但补能、停车、排队、多目的地排序和临时异常仍需要用户自己判断。项目因此聚焦一个命题：

> 用户缺的不是更多信息，而是对下一步的把握。

产品目标不是让 AI 直接“猜”路线，而是让 AI 理解需求、编排地图与服务能力，并把系统结果转成清晰、可靠的驾驶决策。

## 当前可体验能力

- **自然语言行程输入**：同步解析出发地、目的地、出发时间、电量与出行偏好。
- **高德真实算路**：服务端解析地点、返回多条驾车策略，并展示完整地址供用户确认。
- **沿途服务搜索**：结合真实路线搜索充电站和目的地附近停车场。
- **异常 Agent Demo**：支持充电排队、错过出口、道路异常和停车困难四类途中事件。
- **真实途经点重算**：选择备选服务地点后，以真实坐标重新计算路线，而非播放固定动画。
- **可解释建议**：展示方案变化、影响范围与“为什么推荐”，保留用户最终决策权。
- **跨屏信息策略**：定义 AR-HUD、仪表和中控的内容层级与职责分工。
- **可靠性保护**：相同在途请求合并、地图调用排队、一次退避重试、45 秒超时回退与手动重试。

用户输入的地址不会被持久化缓存；并发合并只使用请求哈希，并在请求完成后移除。

## 产品闭环

```text
自然语言需求
    ↓
约束解析与地点确认
    ↓
真实算路 + 充电/停车 POI
    ↓
行程方案与跨屏呈现
    ↓
途中异常检测
    ↓
解释建议 → 用户确认 → 真实重算
```

## 工程验证

2026-09-01 使用 10 条跨城路线完成两轮自动化回归，共 20 次执行：

| 指标 | 结果 | 说明 |
| --- | ---: | --- |
| 真实路线执行 | 20 次 | 同一路线矩阵完成两轮测试 |
| 真实算路链路成功率 | 85% | 17/20 次返回至少一条有效路线 |
| 双类 POI 返回率 | 85% | 充电站与停车场同时返回 |
| 途经点重算成功率 | 85% | 17/20 次完成二次算路 |
| 单轮中位响应时间 | 6.7 / 7.9 秒 | 两轮分别统计 |

这些数字只证明当前工程链路可以运行，同时暴露第三方地图服务的超时与引擎波动；它们不代表用户理解、信任或驾驶安全已经得到验证。完整方法、路线矩阵与限制见 [工程验证记录](docs/route-validation-2026-09-01.md)。

## 技术实现

- React 19 + TypeScript
- Vinext / Vite
- Cloudflare Worker 服务端接口
- 高德 Web Service：地理编码、驾车路径规划与周边 POI
- OpenAI Sites：生产构建与托管
- Node Test：服务端渲染、密钥隔离、错误输入和并发合并回归测试

地图密钥仅保存在服务端环境变量中，不进入浏览器代码或 Git 仓库。

## 本地运行

需要 Node.js `22.13.0` 或更高版本，并在 `.dev.vars` 中配置服务端环境变量：

```text
AMAP_WEB_SERVICE_KEY=你的高德Web服务Key
```

```bash
npm install
npm run dev
```

构建与测试：

```bash
npm test
```

执行真实路线矩阵：

```bash
npm run validate:routes
```
